# 第 1 章 起源：一个约束的由来

> **本章问题**：Node.js 为什么是单线程的？大多数人第一次听到这个事实时的反应是"缺陷"——"因为 JavaScript 单线程，所以 Node.js 只能单线程"。但 2009 年的 JavaScript 并不是唯一选项。这个选择不是被迫的，而是被选中的。本章回到现场，重放那次选择的推导过程。

## 1.1 2009：线程正在吃掉世界

先回到现场。2009 年，你要写一台服务器程序——web 服务器、网关、任何东西——教科书答案只有一种形状：**每个连接一个线程**。连接进来，开一个线程；线程读请求、处理、写响应；连接不走，线程不散。Apache 的 worker 模型是这样，Java 的 Servlet 容器是这样，IIS 也是这样。这个模型对人类极其友好：每个线程里的代码是同步的、线性的、可读的，像一份按顺序执行的菜谱。

但线程不是免费的。翻开账本，一行三项：

**内存**。每个线程需要独立的栈，Linux 上 pthread 默认的栈上限是 8MB，即便按保守的 1MB 实际占用算，一万个连接就是一万个线程，仅栈就是 10GB。连接越多，内存先于 CPU 崩溃。

**调度**。线程一多，内核就要在它们之间切换。一次上下文切换本身是微秒级，真正贵的是切换带来的缓存失效——刚热的缓存被另一个线程冲掉，每个线程都在冷启动中空转。连接数上万时，调度器自身成了瓶颈。

**锁**。多线程共享内存，共享就要锁。死锁、竞态、优先级反转——并发编程的三大经典噩梦全部到齐，而且没有一个能靠"写代码更小心"根除。

这三项成本加在一起，给当年的服务器立了一块天花板，名字叫做 **C10K**——Dan Kegel 在世纪之交提出的挑战：一台机器，**一万条并发连接**。注意数量级：是一万，不是十万、百万。线程模型在一万这个量级上就已经喘不过气。

有意思的是，操作系统其实早就备好了解药。2000 年，FreeBSD 4.1 带来 kqueue；2002 年，Linux 2.5.44 合入 epoll；Windows 那边则有 IOCP。这一族机制做同一件事：**就绪通知**。应用不再派一个线程去守着一个连接等数据，而是把"我对谁感兴趣"登记给内核，内核只在"谁准备好了"的时候举手通知。等待的成本从"一个线程"降到了"一个登记项"。

操作系统把钥匙挂在墙上了，但应用层迟迟没人把它摘下来做成主流。摘的人有，但都待在角落里：nginx（2004）用事件驱动做 web 服务器，Twisted（2002）和 EventMachine 在 Python/Ruby 社区做异步网络库，libevent 把 kqueue/epoll 包成 C 库。它们证明了事件模型能赢，也暴露了问题：**事件驱动当时要么是 C 程序员的手工活，要么是某个语言社区的小众方言，没有一个让普通应用程序员顺手的主流形态**。

缺的不是机制，是载体。2009 年，Ryan Dahl 在 Joyent 做的一件事，就是给这套机制选了一个所有人都没料到的载体。

## 1.2 Dahl 的三条公理

Dahl 没有发明事件驱动。他做的是三件事的焊接——把三个各自成立的选择焊成一条纪律，谁也不能单独拆下来。本书把这三条选择称为**三条公理**，因为后面十五章的每一环都能追溯到其中之一。

**公理一：非阻塞 I/O 是默认纪律，不是可选优化。** 所有 I/O 发起即返回，等待交给内核（网络）或线程池（磁盘，第 5 章会讲这个例外是怎么来的）。应用线程永远不睡。这一条直接消费了 epoll/kqueue 的就绪通知：既然内核会举手，应用就不需要派人去守。

**公理二：应用层单线程。** 不是"开不起更多线程"，而是"一个就够"。一个线程意味着没有共享可变状态，没有锁，没有竞态——线程模型账本上的第三项成本被连根拔掉。同时，回调天然是串行的：事件循环一次只跑一个回调，"同一时刻只有一件事在发生"从程序员的自律变成了运行时的物理事实。

**公理三：载体语言不得提供任何阻塞语法。** 这是最微妙的一条，也是 JavaScript 中标的真正原因。

设想一种语言：它有线程，有阻塞式 `read()`。用它写事件驱动系统会怎样？纪律全靠自觉——总有人会在事件循环里调用那个阻塞 API，一次调用，全体连接陪葬。**在一个允许阻塞的语言里，非阻塞纪律是一个随时会被打破的约定；在一个根本不存在阻塞的语言里，它是唯一活法。**

2009 年的 JavaScript 恰好是后者。它在浏览器里被抚养长大，浏览器出于安全与简洁，从不给它线程，不给它文件 API，不给它 socket——只给它 `setTimeout` 和 `onclick` 这类"登记一个回调"的原语。于是 JS 程序员等待的唯一写法就是回调。对浏览器来说这是语言的贫乏；对事件驱动系统来说，**这是语言的纯洁**。

Dahl 并非一开始就想通了这一层。他最早的 prototype 用 Lua 写——Lua 轻、快、可嵌入，看似完美。但写着写着他发现，Lua 的生态与协程传统总在诱惑他暴露阻塞风格的 API；他需要的不是"能写异步"的语言，而是"写不了同步阻塞"的语言。环顾四周，满足这个条件的主流语言只有一个：JavaScript。

三条公理至此闭环：公理一让等待消失，公理二让锁消失，公理三让公理一不可违背。它们不是三个独立决定，而是同一个决定的三个面。

## 1.3 为什么是 V8：唯一扛得住赌注的引擎

选了 JavaScript，下一个问题立刻到来：用谁的引擎？

2008 年 9 月，Google 随 Chrome 发布并开源了 V8，在 JS 引擎界投下一枚炸弹：**全量 JIT**——JS 不再是解释执行的玩具，热点代码被编译成机器码，性能提升以倍数计。对浏览器来说，这意味着网页应用能跑得快；对 Dahl 来说，这意味着 JS 第一次有资格承载服务器的业务逻辑。

但性能只是入场券。V8 还有两张当时无人能及的牌：

**嵌入性**。V8 以 BSD 许可证开源，提供干净的 C++ API，从第一天起就是为"被别人嵌入"设计的——Chrome 自己就是它的第一个嵌入方。它后来提出的 Isolate 概念（一个独立堆、独立 GC 的执行单元）更是直接成了 Node 的物理边界：第 2 章会讲"一个 Isolate 同一时刻只有一个线程在执行 JS"，第 14 章会讲这个边界如何被"复制"以吃满多核。

**干净的不完整**。这是最反直觉的一点：V8 只管执行 JS，**不碰任何 I/O**。在浏览器里，I/O 能力由浏览器这个"宿主"提供——`fetch`、DOM、定时器都不是 V8 的。裸的 V8 是一个没有手脚的计算引擎。对别人这是缺陷，对 Dahl 这是空间：**V8 不提供的，正是 Node 要补的**。Node 的全部底层工作——Binding（第 3 章）、事件循环（第 4 章）、fd/Buffer/Stream（第三部）——都是在给 V8 这个沙箱装上手脚。

同期并非没有竞争者：Mozilla 的 SpiderMonkey、Apple 的 JavaScriptCore 都在场。选 V8，选的是最激进的性能投入、最开放的许可证、和最"不完整"的边界。赌注下在 2008 年，一年后开奖。

代价同样从这一刻埋下：V8 的沙箱把 JS 关了进去——没有线程、没有 I/O、连 `setTimeout` 都没有（那是宿主的东西，V8 本身不提供）。**Node 必须把"宿主"整个造出来。** 这句话是全书的目录。

## 1.4 没走的那条路

检验一个选择是否清醒，最好的办法是看它的镜像。

2009 年 11 月——与 Node.js 首次公开亮相几乎同一时刻——Google 公布了 Go 语言。Go 回答的是同一个 C10K 问题，走的是镜像的路：**保留同步的写法，把并发的成本交给运行时**。goroutine 起步只有几 KB 栈，阻塞一个 goroutine 只挂起它自己，调度器把它换下去，runtime 在背后做完了线程模型里所有难做的事。

| | Node.js | Go |
|---|---|---|
| 写法 | 回调（日后 Promise/async 缓解） | 同步直线 |
| 纪律由谁承担 | 程序员 | 运行时 |
| 并发单元成本 | 一个闭包，近乎零 | goroutine，KB 级栈 |
| 调度 | 事件循环，显式可见 | runtime 抢占，隐式 |
| 典型失败模式 | 一个长任务卡死全体（第 2 章） | 运行时复杂度内爆 |

两条路没有高下，只有"复杂度放在哪"。Go 把复杂度收进运行时，换程序员写直线代码；Node 把复杂度放进程序员的纪律，换运行时的**极薄与可预测**。

最后这个词值得停顿一秒：可预测。Node 的运行时薄到可以用一条因果链从头推导——这本书之所以能写，正是因为 Node 把复杂性交给了纪律而非魔法。Go 的运行时调度器写不出一本这样的书，不是它不优秀，是它的机制是权衡的堆积，不是公理的推论。

Node 后来也补了线程：worker_threads 于 2018 年实验、2019 年转正。但注意它的姿势——不是共享内存的多线程，而是"复制容器"（第 14 章）。**公理没有被废除，只是被打了补丁**；单线程仍是默认世界，线程是显式出口。

## 1.5 实验：五千条空闲连接的代价

公理一听起来很美，给它一个实证注脚。下面这个程序在一个进程里同时扮演服务器与客户端，建立并持有 5000 条空闲 TCP 连接（两端共 10000 个 socket），然后报出整进程内存：

```js
// ch01-hold.js
const net = require('net');
const N = 5000, BATCH = 250;

const server = net.createServer(() => {});
server.listen(8459, async () => {
  const clients = [];
  for (let base = 0; base < N; base += BATCH) {
    const batch = [];
    for (let i = 0; i < BATCH; i++) {
      batch.push(new Promise((res, rej) => {
        const s = net.connect(8459, '127.0.0.1', () => res(s));
        s.on('error', rej);
      }));
    }
    clients.push(...(await Promise.all(batch)));
  }
  setTimeout(() => {
    console.log('sockets:', clients.length * 2);
    console.log('rss MB:', (process.memoryUsage().rss / 1048576).toFixed(1));
    process.exit(0);
  }, 500);
});
```

运行前需要抬高文件描述符上限（`ulimit -n 12000`）——这个动作本身就是一次剧透：我们碰到的天花板是 fd，第 6 章的主角，前言里那场 `EMFILE` 事故的同一个东西。

实测结果（Node 24，macOS）：

```
sockets: 10000
rss MB: 74.0
```

一万个 socket 端点，整进程 74MB——包含 V8 堆、libuv、两端内核结构在用户态的映射。换成线程模型，5000 条连接就是 5000 个线程，仅栈内存就 ≥5GB，还没算切换。两个数量级的差距不是优化出来的，是**模型出来的**。

再读细一点：这 74MB 里，JS 层为每条空闲连接贡献了多少对象？**零**。没有事件就没有回调，没有回调就没有闭包，JS 堆里甚至不知道这些连接存在。连接活在两个地方：内核的一张 socket 表（第 6 章的 fd），和 libuv 层一个 C++ 句柄（第 11 章的容器零件）。**在事件模型里，"什么都没发生"几乎不花钱**——这正是公理一的经济学的全部秘密：等待的成本被转嫁给了内核，而内核对"等待"的收费便宜得近乎免费。

## 1.6 因果链的第一环

把三条公理摊开，本书的目录就显影了。每条公理都立刻制造一个新问题，每个新问题对应后面的一部：

| 公理 | 立刻产生的问题 | 回答它的章节 |
|---|---|---|
| 非阻塞 I/O | 内核举手了，谁来收割就绪事件？ | 第 4 章 事件循环；第 5 章 两条 I/O 之路 |
| 单线程 | "单线程"到底是什么意思？代价是什么？ | 第 2 章；多核怎么办 → 第 14 章 |
| JS 沙箱 | 没有 I/O 的 JS 如何碰操作系统？ | 第 3 章 Binding；回调纪律的字面实现 → 第 9 章 |

链条的顶端是**单线程**。不是因为它最先被决定，而是因为它是最硬的那个约束：非阻塞纪律可以靠库来维持，沙箱可以靠 Binding 来打破，唯独"一个 Isolate 只有一个线程跑 JS"是 V8 的物理定律，后面所有机制都必须在它面前低头。

2009 年的选择到此完成：一个约束被选中，一台引擎被押注，一种语言从浏览器被抱进了机房。约束的馈赠还没开始兑现——先要弄清楚，这个约束到底把我们关进了什么样的房间。

## 1.7 本质小结

**一句话本质：Node.js 的单线程不是 JavaScript 的局限，而是对 C10K 问题的主动回答——非阻塞 I/O、单线程循环、只许回调的语言，三条公理焊成一条纪律，V8 是唯一扛得住这场赌注的引擎。**

1. C10K = 一万并发连接；线程模型的三项成本：栈内存、上下文切换、锁。
2. kqueue（2000）/epoll（2002）已把"就绪通知"交给应用层，缺的是主流编程模型。
3. 三条公理：非阻塞为纪律、单线程为形态、只许回调的语言为载体；第三条是选 JS 的决定性理由。
4. 选 V8 的三张牌：全量 JIT 的性能、BSD 的嵌入性、"不碰 I/O"的干净不完整。
5. Go 是同一问题的镜像解：纪律交给运行时；Node 交给程序员，换运行时的薄与可推导。
6. 实证：5000 条空闲连接全进程 74MB，线程模型仅栈 ≥5GB；空闲连接在 JS 堆里零对象。

## 下一章引子

公理立下的那一刻，第一个后果已经到账：从此，这个进程里只有一个线程在执行 JS。

但"单线程"这三个字比它听起来更苛刻。它意味着你的一段 `for` 循环跑着的时候，全世界的网络包都在排队；意味着 V8 的垃圾回收和你共享同一个时间轴。这个约束具体长什么样？它又偷偷给了什么馈赠？
